## 3 Почему может пропасть такая возможность?
Потому что м. б. заблокирован порт ssh (22 в моем случае).

## 4 Откройте нужный порт на сервере чтобы восстановить подключение
На сколько понимаю в Alte'е из коробки `iptables` не имеет никаких правил, поэтому все порты открыты:
```bash
sudo iptables -L
Chain INPUT (policy ACCEPT)
target     prot opt source               destination

Chain FORWARD (policy ACCEPT)
target     prot opt source               destination

Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination
```
Можно убедится, что порт 22 прослушивается ssh:

А вообще порт открывается с помощью 2-х команд:
```bash

```

После этого порт все также прослушивается ssh, и я могу подключится по нему.

# Сохраняем
## 6 Сохраняются ли записанные вами правила после перезагрузки?
После перезагрузки машины и подключения к ней правил как и не было ( ╥ω╥ )
```bash
sudo iptables -L
Chain INPUT (policy ACCEPT)
target     prot opt source               destination         

Chain FORWARD (policy ACCEPT)
target     prot opt source               destination         

Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination
```

## 7 Как их сохранить?
Для сохранения нужно воспользоваться командой `iptables-save`. Это выведет текущие правила в формате, который можно использовать для восстановления с помощью команды `iptables-restore`:
```bash
sudo iptables -A INPUT -p tcp -m tcp --dport 22 -j ACCEPT
sudo iptables -A OUTPUT -p tcp --sport 22 -m state --state ESTABLISHED -j ACCEPT
sudo iptables-save
# Generated by iptables-save v1.8.7 on Thu Jan 16 17:14:56 2025
*filter
:INPUT ACCEPT [0:0]
:FORWARD ACCEPT [0:0]
:OUTPUT ACCEPT [1:140]
-A INPUT -p tcp -m tcp --dport 22 -j ACCEPT
-A OUTPUT -p tcp -m tcp --sport 22 -m state --state ESTABLISHED -j ACCEPT
COMMIT
# Completed on Thu Jan 16 17:14:56 2025
```
Поэтому сохраняем эти правила в к-л файле:
```bash
sudo touch /home/iptables-rules
sudo chmod 777 /home/iptables-rules
sudo iptables-save > /home/iptables-rules
sudo reboot
Connection to 192.168.0.184 closed by remote host.
Connection to 192.168.0.184 closed.
```
После перезагрузки правил опять не будет. Для их загрузки нужно прописать `iptables-restore` с данными в нашем файле:
```bash
sudo iptables-restore < /home/iptables-rules
sudo iptables -L
Chain INPUT (policy ACCEPT)
target     prot opt source               destination         
ACCEPT     tcp  --  anywhere             anywhere             tcp dpt:ssh

Chain FORWARD (policy ACCEPT)
target     prot opt source               destination         

Chain OUTPUT (policy ACCEPT)
target     prot opt source               destination         
ACCEPT     tcp  --  anywhere             anywhere             tcp spt:ssh state ESTABLISHED
```

При работе с firewall не рекомендую отключаться от текущей сессии ssh. Лучше подключаться из другой консольки.
